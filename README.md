# Telegram-бот автопостер

Бот собирает посты из вашего канала (через пересылку), сохраняет их в SQLite
с привязкой к хэштегу бренда, и публикует их обратно в канал по расписанию
через inline-панель управления.

## Структура проекта

```
autoposter_bot/
├── database.py           # SQLite: таблицы posts и settings, вся работа с БД
├── utils.py               # Парсинг хэштегов бренда из текста
├── publisher.py           # Публикация одного поста в целевой канал
├── scheduler.py           # APScheduler: фоновая задача автопостинга
├── admin.py                # Inline-панель управления (/start)
├── collector.py            # Сбор постов из пересланных сообщений
├── main.py                 # Точка входа (+ health-check сервер для Render)
├── requirements.txt
├── render.yaml              # Blueprint для деплоя на Render
└── .env.example
```

## Установка

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

1. Скопируйте `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
2. Заполните `.env`:
   - `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather).
   - `ADMIN_ID` — ваш Telegram ID (узнать у [@userinfobot](https://t.me/userinfobot)).
   - `TARGET_CHANNEL_ID` — ID канала для публикации (например `-1001234567890`).
     Можно оставить пустым и задать позже, но пока он не задан, кнопка
     "Запустить" в панели будет недоступна.
3. Добавьте бота **администратором** в канал, куда он должен публиковать посты,
   с правом "Публикация сообщений".

## Запуск

```bash
python main.py
```

## Как пользоваться

1. **Сбор постов**: перешлите боту в личку посты из вашего канала (фото,
   альбомы или текст). Бот сохранит их и покажет, какой бренд-хэштег нашёл
   в тексте (`#LouisVuitton`, `#Gucci` и т.д.). Если хэштега нет — пост
   сохранится без привязки к бренду.
2. **Панель управления**: команда `/start` открывает меню:
   - ▶️/⏸ — запустить/остановить автопостинг;
   - 🏷 Выбрать бренд — постить только определённый бренд или "Все бренды";
   - ⏱ Изменить интервал — 15 мин / 30 мин / 1 час / 2 часа / 4 часа;
   - 📊 Статистика — сколько постов в базе всего и по каждому бренду.
3. Посты публикуются по кругу: сначала те, что ещё ни разу не выходили,
   затем — давно не публиковавшиеся. Повторов подряд не будет, пока не
   закончится весь пул постов выбранного бренда.

## Примечания

- База данных создаётся автоматически при первом запуске (`autoposter.db`
  в корне проекта, либо по пути из `DB_PATH`, см. деплой на Render ниже).
- Только пользователь с `ADMIN_ID` может писать боту и получает ответы —
  остальным бот не отвечает.
- Смена канала публикации через `.env` требует перезапуска бота (кнопки
  для смены канала в панели нет — при необходимости легко добавляется по
  тому же принципу, что и выбор бренда/интервала).

## Деплой на Render

В проекте есть `render.yaml` — Render подхватит его автоматически при
создании Blueprint-сервиса.

### Способ 1: бесплатный тариф (для теста)

1. Залейте проект в GitHub-репозиторий.
2. На [render.com](https://render.com) → **New +** → **Blueprint** → выберите репозиторий.
   Render прочитает `render.yaml` и создаст Web Service на бесплатном тарифе.
3. В настройках сервиса (Environment) заполните переменные:
   `BOT_TOKEN`, `ADMIN_ID`, `TARGET_CHANNEL_ID`.
4. Задеплойте.

**Важно понимать про бесплатный тариф:**
- Free-инстанс "засыпает" без входящих HTTP-запросов ~15 минут — а на бота
  никто, кроме Telegram, "снаружи" не заходит. Чтобы он не засыпал,
  подключите бесплатный пинг-сервис (например
  [cron-job.org](https://cron-job.org) или UptimeRobot), который будет
  дёргать URL вашего сервиса (`https://ваш-сервис.onrender.com/`) каждые
  5–10 минут — на этот адрес отвечает встроенный health-check.
- На бесплатном тарифе **нет persistent-диска**: при каждом рестарте
  контейнера (сон/пробуждение, редеплой) файл `autoposter.db` создаётся
  заново, и все посты, бренды и настройки теряются. Годится, чтобы
  проверить, что бот вообще работает, но не для боевой эксплуатации.

### Способ 2: платный тариф (для продакшена)

1. В `render.yaml` смените `plan: free` на `plan: starter` (от $7/мес),
   при желании — `type: web` на `type: worker` (Background Worker; тогда
   health-check и порт не нужны — эту часть main.py можно не трогать,
   она просто не активируется без `$PORT`).
2. Раскомментируйте в `render.yaml` блок `disk` (persistent-диск) и
   добавьте переменную окружения `DB_PATH=/var/data/autoposter.db` —
   тогда база данных переживёт рестарты и деплои.
3. Передеплойте сервис.

С Background Worker + диском бот ведёт себя так же, как при локальном
запуске — работает постоянно, ничего не засыпает, данные не теряются.
